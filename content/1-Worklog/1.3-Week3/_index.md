### Week 3 Objectives:

* Completed 8 CloudJourney labs (000011, 000063, 000064, 000075, 000002, 000044, 000048, 000012) and 3 videos on the main AWS services and IAM.
* Install AWS CLI v2, configure 2 profiles `default` and `devops`, then build and clean up a system of S3, SNS, IAM, VPC and EC2 using commands only.
* Correctly state the order in which the SDK looks for credentials and the 4 steps AWS uses to sign a request with Signature Version 4.

* Be able to explain AWS STS, IMDSv2 and how to prevent Confused Deputy; move an application on EC2 from access keys to an IAM role and let users sign in through IAM Identity Center.

### Week 3 Achievements:

* Completed 8 CloudJourney labs on AWS CLI, cost, IAM, STS and Identity Center, along with 3 videos on the main AWS services and IAM.
* Used AWS CLI v2 with 2 profiles to work with S3, SNS, IAM, VPC and EC2 and to clean up resources in the correct order.
* Understood that every action on AWS is an API call signed with SigV4; know how to check which credentials are in use with `aws configure list` and `aws sts get-caller-identity`.
* Able to compare the ways of providing credentials:

  + Long-term access keys are only suitable for personal labs and must be deleted when finished
  + Identity Center is for humans
  + Instance profiles via IMDSv2 are for code running on EC2
  + Web identity via OIDC is for CI/CD
* Able to distinguish the group that blocks costs at resource creation time (IAM Condition, SCP, Service Quotas) from the group that only alerts after money has been spent (Budgets, Cost Anomaly Detection, CloudWatch Billing Alarm).
* Able to write the 3 policies `RegionRestrict`, `EC2_FamilyRestrict`, `EC2EBS_Restrict` and know why the broad Allow policy must be removed for them to take effect.
* Able to work out by hand whether IAM allows or denies a request: look for a Deny first, then check SCP, resource-based policy, identity-based policy, boundary and session policy in turn.
* Able to explain why lab 000002 needs the additional `AllowSwitchAdminPolicy` while lab 000044 does not.
* Understood why applications should use roles instead of access keys:

  + IMDSv2 protects against SSRF with a token and the hop limit
  + STS credentials expire automatically; they cannot be revoked individually, so you have to Deny based on `aws:TokenIssueTime`
  + Cross-account access requires a trust policy on the role owner's side and an identity-based policy on the caller's side
