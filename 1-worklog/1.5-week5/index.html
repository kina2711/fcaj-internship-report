- IP range planning for a VPC (lab 000003):
 + AWS reserves 5 IPs in each subnet (the first 4 IPs and the last 1), so a /24 has 251 usable IPs, a /20 has 4,091, and a /28 has 11
 + Each subnet resides in only one AZ, so when designing across multiple AZs you should rely on the AZ ID (e.g. apse1-az1) rather than the AZ name
 + Once created, the CIDR of the VPC and subnets can no longer be resized, and it must not overlap with any network that may need to be connected later
 + In the lab, created VPC ASG with range 10.10.0.0/16, enabled DNS resolution and DNS hostnames, then created 4 subnets: Public Subnet 1 10.10.1.0/24, Public Subnet 2 10.10.2.0/24, Private Subnet 1 10.10.3.0/24, Private Subnet 2 10.10.4.0/24; enabled auto-assign public IP only for the 2 public subnets
- Routing, Internet Gateway and NAT Gateway (labs 000003, 000092):
 + The VPC Router always chooses the route with the longest prefix; the order of entries in the table has no effect; the VPC’s local route is always present
 + A subnet is called public when its route table has a 0.0.0.0/0 route pointing to the Internet Gateway; even so, the instance still needs a public IP or Elastic IP to reach the Internet
 + The Internet Gateway performs 1:1 address translation, so the instance never knows its own public IP
 + The NAT Gateway sits in a public subnet, has an Elastic IP attached and still has to go through the Internet Gateway; the private route table points 0.0.0.0/0 to the NAT Gateway
 + Verify by ssh-ing into the public machine, running ping 8.8.8.8, then ssh-ing onward to the private machine and running ping amazon.com; always check both the outbound path and the return path
- VPC Endpoint (lab 000111):
 + A Gateway Endpoint modifies the route table (adds the prefix list of S3, DynamoDB) and is free; an Interface Endpoint creates an ENI with a private IP in the subnet and changes DNS
 + The lab created Gateway Endpoint s3-gwe for VPC Cloud, then uploaded a 1 GB file to S3 via Session Manager without going out to the Internet
 + Created Interface Endpoint s3-interface-endpoint in 2 AZs, sent a file from the simulated on-premises network over VPN using aws s3 cp --endpoint-url https://bucket.<endpoint DNS name>, then created an alias record in Route 53 so that the on-premises network resolves S3 names to the endpoint
 + An endpoint policy only adds filtering and does not grant permissions; the default Full access policy allows every bucket, so it should not be left that way in production; once traffic goes through the endpoint, the aws:SourceIp condition no longer has any effect
 + Session Manager still works without Internet access thanks to 3 Interface Endpoints ssm, ssmmessages, ec2messages
- Security Group and NACL (labs 000003, 000092):
 + A Security Group is stateful: it remembers connection flows, so return traffic is allowed automatically; a NACL is stateless and evaluates each packet individually, so ephemeral ports must also be opened for return traffic
 + Within a VPC, a rule’s source should reference another Security Group (e.g. Private subnet - SG only allows SSH from Public subnet - SG) instead of an IP range
 + The lab created 3 Security Groups: Public subnet - SG, Private subnet - SG, VPC-Endpoints-SG (HTTPS from 10.10.0.0/16)
- VPC Peering and Transit Gateway (labs 000019, 000020):
 + Creating a new connection only means a path exists; packets can flow only when the route tables on every side point correctly and the NACLs and Security Groups allow it
 + Peering is not transitive: if A connects to B and B connects to C, A still cannot reach C; with many VPCs, switch to Transit Gateway with a hub-and-spoke model
 + Lab 000019 built 2 VPCs 172.31.0.0/16 and 10.10.0.0/16 with CloudFormation, opened ICMP between the two Security Groups, then pinged across the peering
 + Lab 000020 connected 4 VPCs via Transit Gateway lab20-tgw, disabled default association and propagation, then manually created route table lab20-TGW-RT with 4 associations and 4 propagations; association determines which table an attachment looks up, while propagation determines which routes the table contains
 + The MTU of the whole path equals the smallest MTU along the path: within a VPC it is 9001 bytes, but through Transit Gateway it is only 8500
- VPC Flow Logs (lab 000074):
 + Enabled a flow log for the VPC with Filter All, aggregated every 10 minutes, sent to CloudWatch Logs VPCFlowLogGroup via role RoleForVPCFlowLogs
 + The default format has the fields account-id, interface-id, srcaddr, dstaddr, srcport, dstport, protocol, packets, bytes, action (ACCEPT or REJECT)
 + Queried in Log Analytics; flow logs are captured outside the traffic path, so they do not slow down traffic
- CloudFront and Lambda@Edge (labs 000094, 000130):
 + The S3 bucket keeps public access blocked and content is delivered only through CloudFront; in the lab, tried measuring the load time of index.html directly from S3 and then via CloudFront for comparison
 + A distribution can have multiple origins (S3 and EC2) and multiple path-based behaviors; the cache policy determines the cache key, while the origin request policy determines what is forwarded to the origin
 + Code should be placed in the cheapest location that still works correctly: header policy first, then CloudFront Functions, and only last Lambda@Edge
 + Changes at the edge require waiting: a distribution takes 5-10 minutes to deploy, Lambda@Edge about 5 minutes
- Route 53 Resolver for hybrid DNS (lab 000010):
 + Built VPC 10.0.0.0/16 and a simulated on-premises environment with CloudFormation
 + The inbound endpoint lets on-premises DNS resolve names in AWS; the outbound endpoint combined with forwarding rules sends queries for on-premises domain names to the external DNS server
- AWS WAF and Firewall Manager (labs 000026, 000097):
 + Built the sample Juice Shop application behind CloudFront, created a web ACL with managed rules, and logged to S3 (bucket aws-waf-logs-...) via Firehose
 + Each web ACL has a WCU capacity budget; cheap rules (IP set, IP reputation) go first, expensive rules (regex, SQL injection on body) go later
 + Run Count first to avoid wrongly blocking legitimate requests, then switch to Block; when enabling logging, redact the Authorization and Cookie headers
 + WAF only protects requests that pass through it, so the origin must be locked down so that no one can bypass it
 + Lab 000097 created a Security Group opening SSH to 0.0.0.0/0, let the AWS Config rule restricted-ssh flag it as Noncompliant, then enabled AWS Organizations and Firewall Manager to apply policy across the whole organization; audit first, remediate later
- EC2, T family and right-sizing (labs 000004, 000032, 000045):
 + Created a Linux t3.nano instance and a Windows t3.micro instance; to change the instance type you must Stop, choose Change instance type, then Start again
 + The T family works like a CPU credit bucket; t3 and t4g run in unlimited mode by default and may therefore incur charges, so CPUCreditBalance and CPUSurplusCreditBalance need to be monitored
 + Memory metrics are not available by default: you must create role CloudWatchAgentServer (policy CloudWatchAgentServerPolicy), attach it to the instance and install the CloudWatch Agent; right-size the instance first before buying a commitment
 + Lightsail: set alarms that send email notifications when CPU burst capacity drops below 50% and 25%		10/26/202611/01/2026
